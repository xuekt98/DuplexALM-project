## 3.1 Dataset Preparation

This section describes the multi-source data preparation pipeline for training the proposed QwenOmni-3 30B-based full-duplex spoken dialogue model with reinforcement learning. The pipeline is designed around MFIA's four canonical axes of interactivity (pause handling, turn-taking, backchanneling, user interruption) and incorporates data sources from both real human conversations and synthetic augmentation.

### 3.1.1 Data source taxonomy

We collect training data from four complementary categories, each serving distinct training needs across the four interactivity axes:

| Category | Data sources | Axis coverage | Approximate scale |
|---|---|---|---|
| **Real conversational corpora** | Switchboard, Fisher, CallHome, DailyDialog, PersonaPlex synthetic | Pause / Backchannel / Interruption | ~10K hours |
| **Full-duplex speech datasets** | DuplexChat, DuplexDrama, ConversationalVoice | General FD SFT | ~5K hours |
| **RL preference data** | Aligning SDM (Lin et al., 2025), Cocktail-DialogGen (Xin et al., 2026) | RL preference signal | 150K pairs |
| **Benchmark annotations** | FD-Bench, HumDial Challenge, M3-DuplexBench | Evaluation + validation | N/A |

The combined real + synthetic dataset totals approximately **15K hours** of audio after augmentation (see §3.1.4).

### 3.1.2 Four-axis annotation pipeline

Following MFIA (Défossez et al., 2026a), we annotate each conversation with **four canonical interactivity axes**. Each axis has a distinct annotation format and data source.

**Axis 1 — Pause handling.** Pause annotations capture silent segments between user and assistant turns. The annotation criteria require silent segments of duration 300 ms to 3 s. The annotation format is `(start_ms, duration_ms, speaker_id, is_backchannel)`. Source data: Switchboard and Fisher silence annotations.

**Axis 2 — Turn-taking.** Turn-taking annotations capture the latency from turn-end timestamp to the first assistant speech token. The annotation format is `(turn_end_ms, first_token_latency_ms, has_bargein)`. The target distribution follows human-like patterns (200–800 ms latency). Source data: DailyDialog turn-end annotations.

**Axis 3 — Backchanneling.** Backchannel annotations capture short paralinguistic signals (<800 ms) during user speaking. The annotation format is `(position_ms, type, intensity)` where `type ∈ {ack, agreement, surprise, filler}` and `intensity ∈ {low, mid, high}`. Source data: Switchboard backchannel annotations supplemented by TTS-synthesized backchannels (see §3.1.4).

**Axis 4 — User interruption.** Interruption annotations capture barge-in scenarios where the user speaks during assistant output. The annotation format is `(interrupt_position_ms, expected_behavior)` where `expected_behavior ∈ {graceful_yield, immediate_response, complete_thought}`. Source data: CallHome and Fisher barge-in annotations.

**Annotation pipeline.**

1. **Step 1: Automatic annotation.** Use Qwen2.5-72B as the primary annotator. The annotator is prompted with the full conversation context (audio + text + history) and asked to label each of the four axes following the formats above.

2. **Step 2: Human verification.** A 10% subset of the automatically annotated data is verified by human annotators. Inter-annotator agreement target: Cohen's κ ≥ 0.7.

3. **Step 3: Output format.** Each annotated conversation produces a JSON record (see §3.1.6 for the full schema).

### 3.1.3 Quality filtering

We apply a three-stage quality filtering pipeline to ensure training data quality:

| Stage | Filter criteria | Purpose |
|---|---|---|
| **Stage 1: Audio quality** | SNR > 10 dB, no clipping, no music background | Exclude low-quality recordings |
| **Stage 2: Speaker consistency** | Speaker embedding similarity > 0.8 within each speaker | Exclude multi-speaker confusion |
| **Stage 3: Transcript accuracy** | ASR WER < 5%, semantic consistency > 0.9 with human transcript | Exclude mislabeled data |

After filtering, we retain approximately **70% of raw data**, yielding ~7K hours of real conversation data before augmentation.

### 3.1.4 Synthetic augmentation

Real backchannel and interruption data are scarce, particularly for non-English and low-resource settings. We apply four synthetic augmentation strategies:

**A. TTS-based backchannel synthesis.** Because real backchannel annotations are limited, we use **CosyVoice-3** to synthesize backchannel tokens (`<|backchannel|>`, `<|agreement|>`, `<|filler|>`) with:
- Speaker variation: ~100 different voices
- Intensity variation: low, mid, high
- Position variation: random within user turn (avoiding turn-end positions)

**B. Noise injection** (for multi-speaker noisy scenarios, per Cocktail-Talker). Noise is injected at SNR 5–20 dB using NoiseX-92 and MUSAN sources, including babble, cafe, traffic, and music noise types.

**C. Speaker mixing** (multi-speaker scenarios). For Cocktail-Talker-style scenarios, we mix 3–5 overlapping speakers and apply speaker diarization for cleanup.

**D. Speed perturbation.** Speech is slowed/speeded by 0.9×–1.1× while preserving pitch.

After augmentation, the combined dataset totals approximately **15K hours**.

### 3.1.5 Train/validation/test split

We use a **time-based split** to avoid data contamination:

| Split | Proportion | Composition |
|---|---|---|
| **Train** | 80% | Used for Stage 1 SFT + Stage 2 RL |
| **Validation** | 10% | Used for early stopping + hyperparameter tuning |
| **Test** | 10% | Used for final evaluation (held-out) |

**Key constraint**: the test split contains **only real data** (no synthetic augmentation), ensuring that evaluation reflects genuine model performance rather than memorized synthetic patterns.

### 3.1.6 Data format specification

Each training sample follows a unified JSON schema:

```json
{
  "conversation_id": "conv_001",
  "user_audio": "path/to/user.wav",
  "history": [...],
  "axes_labels": {
    "pause": [(1200, 800, "user1", false)],
    "turn_taking": [(3000, 450, false)],
    "backchannel": [(2400, "ack", "low")],
    "interruption": [(3500, "graceful_yield")]
  },
  "action_target": "<|speak|>",
  "text_response": "...",
  "audio_response": "path/to/asst.wav",
  "metadata": {
    "duration_s": 45.2,
    "num_speakers": 2,
    "noise_type": "clean",
    "source": "switchboard"
  }
}
```

The `action_target` field takes one of five values corresponding to the four axes plus a default continue-speaking action:
- `<|pause|>` — silent for next time chunk (Axis 1)
- `<|speak|>` — normal speech continuation (default)
- `<|backchannel|>` — emit a backchannel signal (Axis 3)
- `<|yield|>` — graceful turn surrender (Axis 4)
- `<|interrupt_respond|>` — respond immediately to barge-in (Axis 4)

### 3.1.7 Compute estimate

The total compute budget for data preparation is approximately:

| Step | Resources |
|---|---|
| Data download + storage | 10 TB disk |
| 4-axis automatic annotation (Qwen2.5-72B) | 500 GPU hours |
| Human verification (10% subset) | 1000 person-hours |
| TTS synthesis (backchannel) | 200 GPU hours |
| Noise injection + augmentation | 100 GPU hours |
| **Total data preparation** | **~1000 GPU hours + 1000 person-hours** |

This one-time investment is amortized over the subsequent training stages and is small relative to the model fine-tuning cost.
