## 2.1 全双工口语对话系统的范式演变（简短回顾）

口语对话系统从级联（ASR → LLM → TTS）→ 原生（Moshi 4-stream interleaved token）的范式转变。MFIA（2606.11167v2）的诊断指出关键缺陷：**现有模型仅做 token-level likelihood maximization，未直接优化 interaction-level behaviors**。

## 2.2 4 篇核心参考论文：Methods in Algorithmic Depth

### 2.2.1 MFIA — Multi-Faceted Interactivity Alignment（2606.11167v2）

**算法伪代码**：

```
Algorithm: MFIA Post-Training Alignment
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Input: SFT model π_SFT, human conversation corpus D
Output: Aligned model π_RL

1.  Define axes: A = {pause, turn, backchannel, interrupt}
2.  For each axis a ∈ A:
      a. Extract segments D_a from D matching axis a
      b. Define reward function R_a(segment, model_output)
3.  Define anchor reward R_LLM via LLM-as-judge on response quality
4.  Combined reward: R_total = α · R_LLM + (1-α) · Σ_a λ_a · R_a
5.  Optimize: π_RL = argmax_π E[R_total] with axis-specific RL algorithm
6.  Apply to Moshi/PersonaPlex and evaluate

Key design choices:
- Axis-specific RL algorithm (could be DPO/GRPO/PG)
- LLM-as-judge anchors semantic quality
- Reward weights λ_a per axis (typically tuned)
```

**关键设计**：
- **Four canonical axes of interactivity**：pause / turn / backchannel / interrupt
- **Axis-specific reward functions** 每 axis 设计独立 reward
- **LLM-based anchor reward** 防 axes 训练导致 semantic degradation
- **Post-training alignment** 应用于 Moshi 和 PersonaPlex

**Reward 设计（推断基于论文）**：
- `R_pause`：silence duration distribution match human
- `R_turn`：turn-end → first token latency (200-800ms target)
- `R_backchannel`：appropriate moment + appropriate signal
- `R_interrupt`：graceful response time + acknowledgment
- `R_LLM`：LLM judge on response quality (semantic)

### 2.2.2 DuplexSLA — Speech-Language-Action（2605.20755v2）

**算法伪代码**：

```
Algorithm: DuplexSLA Three-Channel Decoding
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
At each 160ms clock tick:
1.  User audio channel (continuous):
      u_t = AudioEncoder(user_audio_chunk_t)
2.  Assistant audio channel (discrete):
      a_t = AutoregressiveSample(model.a_history, u_t)
3.  Action channel (rate-limited text):
      action_t = AutoregressiveSample(model.action_history, u_t, a_t)
4.  Action types: continue_speak, pause, backchannel, tool_call, etc.
5.  Concatenate outputs as joint next-token distribution

Training (3-stage):
1.  Pre-training: text LLM + audio tokens
2.  SFT: Multi-turn dialogues with action annotations
3.  RL: Action channel optimized via PPO/RLHF
```

**架构图（文字版）**：

```
┌────────────────────────────────────────────────────────┐
│  Single Backbone (Qwen-style LLM)                       │
│                                                         │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐        │
│  │ Channel 1   │ │ Channel 2   │ │ Channel 3   │        │
│  │ User Audio  │ │ Asst Audio  │ │ Action      │        │
│  │ (continuous)│ │ (discrete)  │ │ (text)      │        │
│  └─────────────┘ └─────────────┘ └─────────────┘        │
│         │              │              │                 │
│  160ms chunk      160ms chunk    160ms chunk           │
└────────────────────────────────────────────────────────┘
              ↓ shared clock ↓
```

**关键创新**：
- **Shared 160 ms chunk timeline**（三个 channel 同步）
- **In-conversation planning + tool calling**（不阻塞 audio）
- **Semantic-driven turn-taking**（在 backbone 内处理，不用 VAD）

**训练数据**：natural dialogues + tool-calling scenarios

### 2.2.3 Cocktail-Talker — Turn Action GRPO（2607.27756v1）

**算法伪代码**：

```
Algorithm: Cocktail-Talker Turn Action GRPO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Action tokens: A = {<|respond|>, <|listen|>, <|ignore|>}

Stage 1: Data Generation (Cocktail-DialogGen)
1.  LLM simulates multi-speaker dialogs
2.  Tag each segment with: speaker_id, target_assistant, noise_type
4.  Include edge cases: ambiguous speech, irrelevant speech

Stage 2: Supervised Finetuning
1.  L_supervised = CE_loss(action_token_target, action_pred)
2.  L_supervised += CE_loss(text_response, text_pred)  # only for respond
3.  L_supervised += CE_loss(audio_response, audio_pred)

Stage 3: Turn Action GRPO
1.  For each conversation, for each turn-action decision:
      - Sample G=8 candidate actions
      - Compute reward R = LLM_judge(action_quality, scene_understanding)
2.  GRPO loss: L = -E[advantage · log_prob]
3.  advantage = (R - mean(R)) / std(R)
```

**Reward 设计**：
- `R = LLM_judge(action_quality, scene_understanding)`
- LLM judge 评估 action 是否合适（是否需要回应、对谁回应）

**关键结果**：
- 三个 action token 自然分工：`<|respond|>` / `<|listen|>` / `<|ignore|>`
- 在 noisy social environments 中表现提升

### 2.2.4 Decoupling — DuplexPO（2607.07148v1）

**算法伪代码**：

```
Algorithm: DuplexPO with FCDR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Stage 1: Data Selection
1.  From long human conversations, identify "high-impact windows"
2.  These windows contain: turn transitions, backchannels, barge-ins

Stage 2: Reward Formulation (FCDR)
FCDR = w1 * R_turn_initiation 
     + w2 * R_backchanneling 
     + w3 * R_yielding 
     + w4 * R_regularized_participation

Where:
- R_turn_initiation: reward for appropriate proactive turns
- R_backchanneling: reward for appropriate副语言 timing
- R_yielding: reward for graceful turn surrender
- R_regularized_participation: reward for balanced talk ratio

Stage 3: Optimization (GRPO-style)
1.  π_decouple preserves π_SFT semantic capability
2.  Optimize only on temporal interaction behavior
3.  GRPO objective with FCDR
```

**关键设计**：
- **Preserves** instruction-tuned assistant 的 semantic response capability
- **Optimizes** temporal interaction behavior separately
- **High-impact windows** from long conversations
- **GRPO-style objective** with FCDR

**核心论证原文**：
> "Such an intelligence-dynamics trade-off is not fundamental: conversational dynamics can instead be learned as a separate real-time decision policy from human dialogue data."

## 2.3 其他相关 RL 论文：Methods in Depth

### 2.3.1 ASPIRin — Action Space Projection（2604.10065v1）

**算法伪代码**：

```
Algorithm: ASPIRin Action Space Projection + GRPO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Standard GRPO problem:
L_GRPO = -E[advantage · log π(a_STE | context)]
problem: degrades semantic quality

ASPIRin solution:
1.  Action Space Projection:
      V → V_proj (binary state)
      active_speech ↔ inactive_silence
2.  Modified GRPO loss:
      L_ASPIRin = -E[advantage · log π(action_state | context)]
3.  Rule-based rewards:
      - balanced interruption: penalize premature interruptions
      - response latency: reward 100-800ms latency
4.  Result: eliminates raw-token RL degeneration
```

**关键 insight**：把 text vocabulary 投影到 **coarse-grained binary state**（active speech vs. inactive silence）

**关键结果**：
- **重复 n-gram 比例减少 50% 以上**
- **有效消除 degenerative repetition**（vs standard GRPO）

### 2.3.2 WavAlign — Modality-aware RL（2604.14932v1）

**算法伪代码**：

```
Algorithm: WavAlign Modality-aware Post-Training
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Problem: standard preference optimization fails on SDS

WavAlign solution:
1.  Decompose model parameters:
      θ = θ_semantic ∨ θ_acoustic
2.  Constrain preference updates to θ_semantic only
3.  Improve θ_acoustic via explicit anchoring (CE loss on acoustic tokens)
4.  Dynamically regulate semantic vs acoustic update ratio

Loss:
L_WavAlign = L_preference(θ_semantic) + L_anchor(θ_acoustic)
```

```
Algorithm: Multi-Reward RLAIF for SDS
```

### 2.3.8 FLAIR — Latent Reasoning via ELBO（2603.17837v5）

**算法伪代码**：

```
Algorithm: FLAIR Latent Reasoning
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 2.5 研究空白与本研究定位

### 2.5.1 空白一：模型规模受限

**已有 RL 工作的最常用 base**：Moshi（约 7B）、PersonaPlex（约 7B）、SALMONN-omni（不到 10B）。**针对 30B 级开源全双工基础模型（如 QwenOmni-3 30B）的 RL 微调仍是空白**。

**QwenOmni-3 30B 的优势**：(1) 多模态理解能力强；(2) 已有 audio 适配基础；(3) 计算资源足以支撑 RL 训练。但其在全双工交互上的 RL 适配**尚未被系统研究**。

### 2.5.2 空白二：单一交互 axis 优化为主

已有 RL 工作往往聚焦单一 axis：ASPIRin（仅 timing）、Dual-Axis GRM（仅 semantic + timing）、Cocktail-Talker（仅 respond/listen/ignore）。

**Multi-Faceted Interactivity Alignment（MFIA）虽提出 4-axis 框架**（pause handling / turn-taking / backchanneling / user interruption），但**仅在 Moshi（~7B）与 PersonaPlex（~7B）上验证**，尚未在 30B 量级模型上验证其可扩展性。

### 2.5.3 空白三：缺乏稳定的"语义 vs 交互"权衡

- **ASPIRin** 已显示 raw-token RL 会导致 repetition
- **WavAlign** 提出 modality-aware RL（仅在 semantic channel 更新）
- **MFIA** 提出 LLM judge anchor reward
- **SteerDuplex** 发现 reward hacking 风险（模型可学到 incomplete response）

**这些权衡机制在 30B 量级模型上的效果与可扩展性仍未验证**。具体问题：
1. 在 30B 模型上，anchor reward 的权重应该如何调整？
2. 30B 模型是否更容易发生 reward hacking？
3. WavAlign 的 modality-aware 在大模型上是否依然有效？

### 2.5.4 本研究定位

针对上述空白，本研究（详见第 3 章）拟在 QwenOmni-3 30B 上：

1. **实现 MFIA 的 4-axis 框架**，但对每个 axis 选择最适合的 RL 算法：
   - **Pause Handling**：**DPO**（二元决策）
   - **Turn-Taking**：**GRPO + ASPIRin's Action Space Projection**
   - **Backchanneling**：**Conditional DPO**（基于对方是否在说话）
   - **Interruption**：**Policy Gradient + FSM state machine**

2. **保留 ASPIRin 的核心 insight**：Action Space Projection 把 vocab 投影到 binary state，**避免 raw-token RL 的 repetition**

3. **保留 MFIA 的 LLM Judge anchor**：防止 axes 训练导致 semantic collapse

4. **引入 WavAlign 的 modality-aware 思想**：RL 更新限制在 semantic channel，acoustic behavior 通过 explicit anchoring

5. **在统一 benchmark 上评估**：MMAE + DuplexBench + APEX-Voice + Cocktail-Talker Eval

本研究的核心贡献是**首次在 30B 量级全双工模型上系统实现并验证多轴交互对齐方法**，为工业级（30B+）全双工系统的 RL 训练提供可扩展的方法论。
