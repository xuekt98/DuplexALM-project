## 3.3 Training Recipe

This section describes the complete training pipeline for the proposed QwenOmni-3 30B-based full-duplex spoken dialogue model with multi-axis reinforcement learning.

### 3.3.1 Training overview

We adopt a three-stage training pipeline that progressively refines the model's interactivity while preserving its semantic capabilities:

```
Stage 0: Pre-training (QwenOmni-3 base model, already complete)
    ↓
Stage 1: Supervised Fine-Tuning (SFT) on 4-axis annotated dialogues
    ↓ baseline interactivity behaviors learned
Stage 2: Per-axis Reinforcement Learning (RL) — four axes trained concurrently
    ├─ Stage 2a: Pause Handling via DPO
    ├─ Stage 2b: Turn-Taking via GRPO + ASPIRin's Action Space Projection
    ├─ Stage 2c: Backchanneling via Conditional DPO
    ├─ Stage 2d: Interruption via Policy Gradient with FSM
    └─ Stage 2e: LLM Judge Anchor (concurrent gating, frozen Qwen2.5-72B)
    ↓ axes-specific behaviors optimized
Stage 3: Joint Refinement (optional) — all axes trained jointly with anchor
    ↓ final unified model
```

The complete pipeline consumes approximately **50K GPU hours** on 32-GPU nodes (e.g., H100-80GB), with the per-axis RL stages running in parallel to reduce wall-clock time.

### 3.3.2 Stage 1: Supervised Fine-Tuning

**Objective.** Teach the model to produce 4-axis action tokens alongside text and audio responses, establishing baseline interactivity behaviors.

**Loss function.** The SFT loss combines cross-entropy across all three channels and the four axis heads:

```
L_SFT = λ_text · CE(text_pred, text_target)
      + λ_audio · CE(audio_pred, audio_target)
      + λ_action · CE(action_logits, action_target)
      + λ_axes · Σ_a CE(axis_a_pred, axis_a_target)
```

with default weights λ_text=1.0, λ_audio=1.0, λ_action=0.5, λ_axes=0.3.

**Data.** 80% train split of the 4-axis annotated dataset (§3.1.5).

**Hyperparameters.**

| Parameter | Value |
|---|---|
| Optimizer | AdamW |
| Learning rate | 2e-5 |
| Weight decay | 0.01 |
| Batch size | 256 (8 per GPU × 32 GPUs) |
| Sequence length | 4096 tokens |
| Epochs | 3 |
| LR schedule | Cosine decay with 1000-step warmup |
| **Compute** | **~10K GPU hours** |

### 3.3.3 Stage 2a: Pause Handling via DPO

**Objective.** Optimize the binary speak/silence decision to match human silence duration distributions.

**Algorithm.** Direct Preference Optimization (DPO) with the Stage 1 SFT model as the reference policy π_ref:

```
For each (chosen, rejected) pair in pause preference data:
    chosen_logits = pause_head(LLM(chosen_audio_emb))
    rejected_logits = pause_head(LLM(rejected_audio_emb))
    
    chosen_logp  = log_softmax(chosen_logits[:, :, 1])   # "speak" prob
    rejected_logp = log_softmax(rejected_logits[:, :, 1])
    
    ref_chosen_logp  = log_softmax(π_ref(chosen_audio)[:, :, 1])
    ref_rejected_logp = log_softmax(π_ref(rejected_audio)[:, :, 1])
    
    L_DPO = -log σ(β · (chosen_logp - ref_chosen_logp) - β · (rejected_logp - ref_rejected_logp))
```

**Reward signal.** Match human silence duration distribution (300ms–3s typical, with peak around 500–800ms).

**Hyperparameters.**

| Parameter | Value |
|---|---|
| DPO beta | 0.1 |
| Learning rate | 5e-6 |
| Epochs | 2 |
| **Compute** | **~5K GPU hours** |

### 3.3.4 Stage 2b: Turn-Taking via GRPO with Action Space Projection

**Objective.** Optimize response latency while avoiding the raw-token RL degeneration problem identified by ASPIRin (2604.10065v1).

**Algorithm.** Group Relative Policy Optimization (GRPO) over an Action Space Projection of the vocabulary. The Action Space Projection maps the text vocabulary into a coarse-grained binary state (active speech vs. inactive silence), following ASPIRin's central insight that this isolation prevents the generative collapse that afflicts raw-token RL:

```
For each group of G=8 candidate responses:
    For each sample s in group:
        output = model(sample.user_audio)
        latency = output.turn_taking                 # predicted latency in ms
        
        # Reward: balanced interruption vs latency
        if 100 < latency < 800:
            reward_s = 1.0 - |latency - 400| / 400    # peak at 400ms
        else:
            reward_s = -1.0
        
        # ASPIRin: project text vocab to binary state
        binary_state = ActionSpaceProjector(output.hidden)   # (B, T, 2)
        
        # Anchor: semantic score (from frozen LLM judge)
        semantic = LLMJudge(output.text)
        total_reward_s = 0.7 · reward_s + 0.3 · (semantic - 0.5)
    
    advantages = (group_rewards - mean) / (std + 1e-8)
    
    # GRPO loss with Action Space Projection
    log_probs = binary_state[:, -1, 1]    # P(active speech)
    loss = -(log_probs · advantages).mean()
```

**Hyperparameters.**

| Parameter | Value |
|---|---|
| GRPO group size | 8 |
| Learning rate | 5e-6 |
| Epochs | 2 |
| Anchor weight | 0.3 on semantic score |
| **Compute** | **~10K GPU hours** |

### 3.3.5 Stage 2c: Backchanneling via Conditional DPO

**Objective.** Train backchannel triggering conditioned on whether the other party is currently speaking, using a VAD signal as context.

**Algorithm.** Conditional DPO with VAD signal embedded alongside hidden states:

```
For each batch in backchannel preference pairs:
    vad_signal = batch.vad_state            # (B, T, 1) — is other party speaking?
    
    chosen_emb  = LLM(batch.chosen_audio)
    rejected_emb = LLM(batch.rejected_audio)
    
    chosen_bc  = backchannel_head(chosen_emb, vad_signal)
    rejected_bc = backchannel_head(rejected_emb, vad_signal)
    
    # chosen: backchannel triggered at right moment
    chosen_logp  = log_softmax(chosen_bc[:, -1, 1])
    rejected_logp = log_softmax(rejected_bc[:, -1, 1])
    
    L_CDPO = -log σ(β · (chosen_logp - rejected_logp))
```

**Reward signal.** Appropriate moment (within user turn but not at boundaries) + appropriate signal (ack, agreement, surprise, filler).

**Hyperparameters.**

| Parameter | Value |
|---|---|
| DPO beta | 0.1 |
| Learning rate | 5e-6 |
| Epochs | 2 |
| **Compute** | **~5K GPU hours** |

### 3.3.6 Stage 2d: Interruption via Policy Gradient with FSM

**Objective.** Train the interruption policy as a Finite State Machine with 5 states, ensuring graceful yield and timely response to barge-in.

**FSM topology.**

```
LISTENING → ABOUT_TO_SPEAK → SPEAKING → (INTERRUPTED → YIELDED | continue)
```

**Algorithm.** Policy Gradient with cross-entropy auxiliary loss over FSM state sequences:

```
For each scenario in interruption_scenarios:
    output = model(scenario.user_audio)
    fsm_logits = output.fsm_logits     # (B, T, 5)
    
    target_seq = scenario.expected_fsm_states
    fsm_loss = CE(fsm_logits.reshape(-1, 5), target_seq.flatten())
    
    # PG term
    log_probs = log_softmax(fsm_logits)
    fsm_reward = compute_fsm_reward(scenario)  # graceful yield + response time
    pg_loss = -(log_probs · fsm_reward).mean()
    
    loss = fsm_loss + 0.5 · pg_loss
```

**Reward signal.** Graceful yield (yield rate > 90%) + response time (< 300ms).

**Hyperparameters.**

| Parameter | Value |
|---|---|
| Learning rate | 5e-6 |
| Epochs | 2 |
| **Compute** | **~5K GPU hours** |

### 3.3.7 Stage 2e: LLM Judge Anchor (concurrent gating)

**Objective.** Prevent the axes training stages from degrading the model's semantic capability — the key risk identified by SteerDuplex (reward hacking via incomplete responses).

**Algorithm.** The LLM Judge Anchor runs concurrently with all Stage 2 axes training. A frozen Qwen2.5-72B judges the semantic quality of model outputs; the result gates the axes loss weight:

```
For each batch in axes training:
    output = model(batch)
    semantic_score = LLMJudge.compute(
        response_text = output.text,
        context = batch.history
    )
    
    # Adaptive axes weight (anchor gating)
    axes_weight = max(0, (semantic_score - 0.4) / 0.6)
    axes_weight = min(axes_weight, 1.0)
    
    # Apply weighted axes loss
    axes_loss = weighted_loss(batch, axes_weight)
    axes_loss.backward()
```

**Hyperparameters.**

| Parameter | Value |
|---|---|
| Judge model | Qwen2.5-72B (frozen) |
| Anchor threshold | 0.4 (below this, axes_weight → 0) |
| Anchor weight α | 0.3 (semantic in combined reward) |
| **Compute** | **~5K GPU hours (concurrent, no extra wall-clock cost)** |

### 3.3.8 Stage 3: Joint Refinement

**Objective.** All four axes trained jointly with the LLM Judge Anchor gating, producing the final unified model.

**Algorithm.** Joint loss with anchor weighting:

```
For each batch in batches:
    output = model(batch)
    
    # Per-axis rewards
    r_pause       = compute_pause_reward(output, batch)
    r_turn        = compute_turn_reward(output, batch)
    r_backchannel = compute_backchannel_reward(output, batch)
    r_interruption = compute_interruption_reward(output, batch)
    
    # Anchor gating
    semantic = LLMJudge.compute(output.text)
    axes_weight = gate(semantic)    # [0, 1]
    
    # Joint loss: axes when semantic high, semantic preservation when axes_weight low
    L_joint = axes_weight · (r_pause + r_turn + r_backchannel + r_interruption)
            + (1 - axes_weight) · L_semantic
    
    L_joint.backward()
```

**Hyperparameters.**

| Parameter | Value |
|---|---|
| Learning rate | 3e-6 (lower than per-axis) |
| Epochs | 1 |
| **Compute** | **~10K GPU hours** |

### 3.3.12 Monitoring metrics

We track the following metrics throughout training to detect regressions and validate the LLM Judge Anchor:

| Metric | Target | Monitors |
|---|---|---|
| Pause handling accuracy | KL divergence from human < 0.05 | Axis 1 quality |
| Turn-taking latency p50/p95 | < 300ms / < 800ms | Axis 2 quality |
| Backchannel appropriateness | LLM judge score > 0.7 | Axis 3 quality |
| Interruption graceful yield rate | > 90% | Axis 4 quality |
| Semantic quality (anchor) | > 0.6 throughout | Axis health |
| Duplicate n-gram ratio | < 5% (ASPIRin baseline) | ASPIRin effectiveness |
| Overall conversation MOS | human-acceptable | End-to-end quality |

If the anchor semantic score drops below 0.6 for more than 2 consecutive evaluation batches, training is paused and the axes weights are reduced before resuming — providing early detection of reward hacking.

**Document summary**: This Training Recipe document specifies a complete 3-stage pipeline (SFT → 4-axis RL with anchor gating → joint refinement) that consumes ~50K GPU hours total. Key innovations over prior work include (1) the ASPIRin Action Space Projection preventing raw-token degeneration, (2) the MFIA-derived LLM Judge Anchor preventing reward hacking via incomplete responses, and (3) WavAlign's modality-aware masking preventing acoustic degradation during RL updates.
