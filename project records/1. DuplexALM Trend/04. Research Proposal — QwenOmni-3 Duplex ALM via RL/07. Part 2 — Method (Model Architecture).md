## 3.2 Model Architecture

This section details the modifications we apply to QwenOmni-3 30B to build an end-to-end full-duplex spoken dialogue model with reinforcement learning. The architecture integrates insights from DuplexSLA's three-channel formulation, MFIA's four-axis interactivity framework, ASPIRin's Action Space Projection, and WavAlign's modality-aware RL training, all unified through a single QwenOmni-3 backbone with LoRA-based fine-tuning.

### 3.2.1 QwenOmni-3 30B base architecture

QwenOmni-3 30B is the multimodal foundation model from Alibaba Tongyi Lab. Its architecture comprises:

| Component | Parameters | Function |
|---|---|---|
| Audio Encoder | ~400M | 16 kHz audio → audio tokens |
| Text Tokenizer | BPE-style | text → text tokens |
| LLM Backbone (Qwen3-style) | 30B | multi-modal reasoning |
| Speech Decoder (CosyVoice-style) | ~400M | speech tokens → waveform |
| **Total** | ~30.8B | multimodal end-to-end |

The base QwenOmni-3 30B is **not natively full-duplex capable**—it processes audio input/output on a turn-by-turn basis. The modifications described in §3.2.2 through §3.2.7 convert it into a true full-duplex, multi-axis-interactivity-aligned spoken dialogue model.

### 3.2.3 Modification 1: Three-channel output heads (DuplexSLA-inspired)

Our three-channel output follows DuplexSLA's three-channel formulation, with QwenOmni-3-specific implementation details:

**Channel 1 — Text Response.**
- *Task:* Generate assistant text tokens
- *Implementation:* Reuse QwenOmni-3's existing text output head
- *Fine-tuning:* LoRA r=64 on existing head
- *Role:* Serves as semantic anchor (input to MFIA's LLM-judge)

**Channel 2 — Audio Tokens.**
- *Task:* Generate assistant speech tokens (CosyVoice codec style)
- *Implementation:* Reuse QwenOmni-3's speech decoder output
- *Fine-tuning:* LoRA r=64 on speech decoder adapter
- *Role:* Target output for turn-taking optimization (response latency)

**Channel 3 — Action Stream** (new, key innovation).
- *Task:* Output 4-axis action tokens (`<|pause|>` / `<|speak|>` / `<|backchannel|>` / `<|yield|>` / `<|interrupt_respond|>`)
- *Implementation:* Newly added output head, replacing no existing component
- *Fine-tuning:* LoRA r=8x (more focused, since RL training centers here)
- *Role:* Optimization target for 4-axis RL
- *160 ms chunk timeline:* Aligned with DuplexSLA

### 3.2.4 Modification 2: Four-axis heads (MFIA-style)

Four independent heads, each targeting one axis:

```python
class AxisHead(nn.Module):
    """Base class for 4 axis heads"""
    def __init__(self, hidden_dim, output_dim):
        super().__init__()
        self.proj = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.GELU(),
            nn.Linear(hidden_dim, output_dim)
        )
```

**Head 1 — PauseHandlingHead (Axis 1).**
- *Task:* Binary decision (speak / silence)
- *Architecture:* `Linear(hidden, 512) → GELU → Linear(512, 2)`
- *Training:* DPO (see §3.3.3)
- *Reward function:* Match human silence duration distribution

**Head 2 — TurnTakingHead (Axis 2).**
- *Task:* Predict response latency
- *Architecture:* `Linear(hidden, 512) → GELU → Linear(512, 1) → ReLU` (latency in ms)
- *Training:* GRPO + Action Space Projection (see §3.3.4)
- *Reward function:* Balanced interruption + response latency (100–800 ms target)

**Head 3 — BackchannelHead (Axis 3).**
- *Task:* Conditional on VAD signal
- *Architecture:* `Linear(hidden + 1_vad, 512) → GELU → Linear(512, 2)`
- *Key design:* VAD signal (1-dim) as context embedding
- *Training:* Conditional DPO
- *Reward function:* Appropriate moment + appropriate signal

**Head 4 — InterruptionHead (Axis 4).**
- *Task:* FSM-based state prediction
- *Architecture:* `Linear(hidden, 512) → GELU → Linear(512, 5)` (5 FSM states)
- *5 FSM states:* LISTENING / ABOUT_TO_SPEAK / SPEAKING / INTERRUPTED / YIELDED
- *Training:* Policy Gradient + FSM state transitions
- *Reward function:* Graceful yield + response time

### 3.2.5 Modification 3: ASPIRin's Action Space Projection

Direct raw-token RL optimization causes repetition (as demonstrated by ASPIRin). We adopt ASPIRin's **Action Space Projection** to prevent this:

```python
class ActionSpaceProjector(nn.Module):
    """Project text vocab to binary action state (ASPIRin)"""
    def __init__(self, vocab_size, hidden_dim):
        super().__init__()
        self.active_proj = nn.Linear(hidden_dim, hidden_dim)
        self.inactive_proj = nn.Linear(hidden_dim, hidden_dim)
    
    def forward(self, hidden_states):
        # Project to binary: active speech vs inactive silence
        active_logits = self.active_proj(hidden_states)
        inactive_logits = self.inactive_proj(hidden_states)
        return torch.cat([inactive_logits, active_logits], dim=-1)
```

**Effect:** Maps the vocabulary to a coarse-grained binary state (active speech vs. inactive silence). GRPO optimizes over this binary space, avoiding raw-token degeneration. ASPIRin reports **>50% reduction in duplicate n-grams**.

### 3.2.6 Modification 4: LLM Judge Anchor module (new, frozen)

A separate, **frozen Qwen2.5-72B** serves as the semantic quality judge:
- *Input:* Model output (audio + text response)
- *Output:* Semantic quality score ∈ [0, 1]
- *Role:* **Gates axes training**—when score < 0.6, axes_weight is reduced

```python
class LLMJudgeAnchor(nn.Module):
    """Separate frozen Qwen2.5-72B for semantic anchor"""
    def __init__(self, judge_model_path='qwen2.5-72b'):
        super().__init__()
        self.judge = AutoModel.from_pretrained(judge_model_path)
        # Freeze judge - never trained
        for param in self.judge.parameters():
            param.requires_grad = False
    
    def compute(self, response_text, context):
        prompt = f"""Rate the quality of this response on a 0-1 scale.
        Context: {context}
        Response: {response_text}
        Score:"""
        score = self.judge.generate(prompt)  # 0-1
        return score
```

**Integration with axes RL:**
- axes_weight = max(0, (semantic_score - 0.4) / 0.6)
- axes_weight ∈ [0, 1], dynamically adjusted
- This is MFIA's central mechanism

### 3.2.7 Modification 5: WavAlign Modality-Aware Mask

WavAlign argues that RL updates should be restricted to the **semantic channel**, preventing damage to the acoustic model:

```python
class ModalityAwareMask(nn.Module):
    """Constrain RL updates to semantic channel (WavAlign)"""
    def __init__(self, hidden_dim):
        super().__init__()
        # Semantic channel mask: mask semantic updates only
        self.semantic_mask = nn.Parameter(torch.ones(hidden_dim))
        self.acoustic_anchor = nn.Linear(hidden_dim, hidden_dim)
    
    def forward(self, semantic_grad, acoustic_grad):
        # Apply mask to semantic gradient
        masked_semantic = semantic_grad * self.semantic_mask
        # Acoustic via explicit anchoring (not gradient update)
        acoustic_anchored = self.acoustic_anchor(acoustic_grad.detach())
        return masked_semantic + acoustic_anchored
```

**During training:** RL gradients update only semantic-channel parameters; the acoustic channel is improved through explicit anchoring rather than gradient updates.

### 3.2.8 Parameter and training strategy summary

| Component | Parameters | Training strategy |
|---|---|---|
| Audio Encoder | 400M | frozen |
| Text Tokenizer | — | frozen |
| LLM Backbone | 30B | LoRA r=64 |
| Multimodal Fusion | — | frozen |
| Speech Decoder | 400M | LoRA r=64 |
| **Channel 3 (Action)** | **~50M** | LoRA r=8x |
| 4 Axis Heads | ~50M total | LoRA r=8 |
| Action Space Projector | ~5M | LoRA r=8 |
| LLM Judge Anchor | 72B (Qwen2.5-72B) | **frozen** |
| Modality-Aware Mask | ~5M | trainable |
| **Total trainable** | **~31B** (with LoRA) | — |
| **Effective trainable** | **~250M** (LoRA) | — |

**Why LoRA-based:**
- 30B full-parameter fine-tuning cost-prohibitive
- LoRA preserves base model capabilities while learning task-specific behaviors
- Each axis head's LoRA is independent, enabling per-axis Stage 2 training
- ASPIRin's key insight: avoid raw-token degeneration

### 3.2.9 Complete forward pass

```python
def forward(self, user_audio, history=None):
    # 1. Audio encoding (frozen)
    user_emb = self.audio_encoder(user_audio)  # (B, T_audio, D)

    # 2. LLM backbone (LoRA fine-tuned)
    hidden = self.llm_backbone(user_emb, history=hidden)  # (B, T, D)

    # 3. Action Space Projection (binary state)
    action_logits = self.action_projector(hidden)  # (B, T, 2)

    # 4. 4-Axis Heads (parallel)
    pause_decision    = self.pause_head(hidden)               # (B, T, 2)
    tt_latency         = self.turn_taking_head(hidden)          # (B, T, 1)
    bc_trigger         = self.backchannel_head(hidden, vad_signal) # (B, T, 2)
    fsm_state, fsm_logits = self.interruption_head(hidden)      # (B,), (B, T, 5)

    # 5. Modality-Aware Mask (semantic only RL updates)
    masked_semantic = self.modality_mask(semantic_grad)

    # 6. Speech Decoder (LoRA)
    assistant_audio = self.speech_decoder(hidden)

    # 7. Text Response (LoRA)
    assistant_text = self.text_head(hidden)

    # 8. LLM Judge Anchor (frozen, inference only)
    semantic_score = self.llm_judge(assistant_text, history)

    return {
        'assistant_audio': assistant_audio,
        'assistant_text': assistant_text,
        'action': action_logits,
        'pause': pause_decision,
        'turn_taking': tt_latency,
        'backchannel': bc_trigger,
        'fsm_state': fsm_state,
        'fsm_logits': fsm_logits,
        'semantic_score': semantic_score,
        'continuous_focus': fsm_state == 'SPEAKING',  # for streaming
    }
```

### 3.2.10 Inference mode

After training, inference proceeds as:

```python
def inference(self, user_audio_chunk, history=None):
    # 1. Encode audio
    user_emb = self.audio_encoder(user_audio_chunk)

    # 2. Backbone forward
    hidden = self.llm_backbone(user_emb, history=history)

    # 3. Action Space Projection → binary action
    action_logits = self.action_projector(hidden)
    action = torch.argmax(action_logits, dim=-1)  # 0 or 1

    if action == 0:  # silence
        return None  # don't speak

    # 4. Determine which axis (if multiple actions possible)
    pause = self.pause_head(hidden)  # binary: speak/silence
    # ... etc

    # 5. Generate response (text + audio)
    text = self.text_head.generate(hidden)
    audio = self.speech_decoder(hidden)

    return {'text': text, 'audio': audio}
```

**Key inference-time design choices:**
- 160 ms chunk timeline (aligned with DuplexSLA)
- Continuous turn-around latency < 300 ms (industry standard)
- ASPIRin's binary action space reduces decision latency

### 3.2.11 Architecture rationale

The proposed architecture is justified by:

1. **3-channel design (DuplexSLA-inspired):** The triple-channel formulation (user audio + assistant audio + textual action) is necessary for true full-duplex interaction without turn-boundary constraints. Listening, speaking, planning, and tool calling unfold on a shared 160 ms clock.

2. **4-axis heads (MFIA-style):** Interactivity is multi-faceted. A single RL target is insufficient. We decompose into pause handling, turn-taking, backchanneling, and user interruption, each with its own reward and training algorithm.

3. **ASPIRin's Action Space Projection:** Raw-token RL optimization causes repetitive degeneration. Projecting to a coarse-grained binary state (active speech vs. inactive silence) decouples "when to speak" from "what to say" and avoids this pathology.

4. **LLM Judge Anchor:** Direct optimization of behavioral rewards (turn-taking latency, backchannel frequency) risks destroying the model's semantic capability. The frozen LLM judge provides a non-degrading semantic quality score that gates axes training.

5. **WavAlign Modality-Aware Mask:** Sparse preference supervision interacts poorly with dense speech generation under shared-parameter updates. Constraining RL updates to the semantic channel preserves acoustic model quality.

These five modifications collectively enable stable, scalable multi-axis interactivity alignment for a 30B-scale full-duplex foundation model.
