## 二、每个方向的详细核查结果

### ★★★★★ T1: Audio Data Curation Agent — **0 strict hits，真空 niche**

**严格筛选结果**：0 篇

**为什么是真空**：
- 检索关键词：audio data curation, audio dataset agent, audio annotation agent, automatic audio dataset, audio data pipeline, audio data synthesis, audio data augmentation, audio quality assessment, dataset condensation audio, audio data engine, audio corpus construction
- **所有命中的论文都是 dataset 论文**（ChinaVoices Challenge, VAANI Noise Event, AudioWorldSim, TUTTI, DocTalkBN 等）——它们是**产出数据集**，不是"自动策划数据集"
- 没有任何论文做"**用 LALM 自动策划 audio 数据集**"

**最近相关论文（不严格但相关）**：
- **ChinaVoices Challenge 2026** (2609.03471) — 数据集 + 任务，但人工策划
- **TUTTI** (2609.00640) — "fully synthesized data" for audio-to-score transcription
- **AudioWorldSim** (2608.21075) — binaural datasets，合成但没 agent
- **VersaDB** (2608.22795) — multimodal data storage（基础设施）
- **ACE-Data-0** (2607.28625) — Embodied Data Engine（Hugging Face）
- **Audio-to-Score Transcription using Pre-trained Features, Data Augmentation** (2608.06165)

**关键判断**：**这是真正的真空 niche**。痛点（audio 数据稀缺、人工策划耗时）与解决方案（用 LALM agent 自动执行 data curation pipeline）的组合**没有被任何论文做过**。

**Niche 优势**：
- 痛点真实（audio 数据确实稀缺，特别是 SFX、长音频、版权音乐）
- AIGC 数据 pipeline 经验可直接迁移（dataset distillation, dataset condensation, synthetic data 等都是 AIGC 经典）
- 与 duplex ALM / music gen 团队都有接口（都需要更多数据）
- 工程可行，无技术风险

**Risk 中-低**：与 Spotify / Apple Music 等公司有 data engine，但学术界尚未系统化。

### ★★★★ T2: Audio Editing Agent — **4 strict hits + 多个 audio agent**

- **RIME** (2607.19605) — Large-Scale Agentic Music Post-Production ← **音乐后期制作 agent，最接近**

**关键判断**：**"Audio Editing Agent" 这个特定组合仍有 niche**——最接近的是 RIME（音乐后期制作 agent）和 SAO-Instruct（自然语言音频编辑），但都不是 "audio editing agent" 的完整框架。

**Risk 中**：需要构建 tool 库（ASR, separation, generation, editing, watermarking 等）。

### ★★★★ T4: Audio-Dependency Verification — **3 strict hits，niche 存在**

**严格筛选结果**：3 strong hits — **确实 niche**

**代表 SOTA**：
- **Do Audio Language Models Use Paralinguistic Evidence? Counterfactual Audits for Response Evaluation** (2608.06718) — **直接相关**：counterfactual audit
- **Auditing Protocol-Level Shortcuts in Large Audio Language Model Judges for Speech Evaluation** (2607.13477) — **直接相关**：audit protocol
- **RAIL: Rethinking Auditory Intelligence in LALMs with a CHC-Grounded Benchmark** (2606.11260) — **直接相关**：auditory intelligence benchmark with grounding

**关键判断**：**audio benchmark audit / dependency verification 是新兴 niche**，3 篇 strict hits 都是 2026 年工作。这是**与我上一轮 brainstorm的 Audio-Dependency Verification Framework** 直接重叠的方向。

**与我的建议的差异**：
- 已有 3 篇做类似方向，但**每篇侧重不同**：
  - Do Audio LMs Use Paralinguistic Evidence? → counterfactual audit（我的 ADF pipeline 思想）
  - Auditing Protocol-Level Shortcuts → protocol-level shortcuts（与 ADQA ADF 类似）
  - RAIL → CHC-Grounded Benchmark（更系统化）
- **尚无**整合"silent-audio probing + per-option perplexity + LLM commonsense check + human review"的完整 framework

**可做的差异化**：
- 不重复 RAIL 的 benchmark 框架（更系统化版本）
- 主攻**集成 audit pipeline**（综合多个 audit 方法成可部署 framework）
- 或**specific benchmark audit**（如 AudioBench, AIR-Bench, MMAE 等的 audit）

**Niche 优势**：
- 已有前期工作证明 niche 真实
- DCASE 2026 Task 5 ADF pipeline 可直接复用
- 与 duplex ALM 团队契合（直接服务于 LALM 评测）

**Risk 中**：3 篇工作方向高度重叠，需要明确差异化点。

## 五、深度反思

### 反思 1：niche 收窄的层级

每一轮核查都揭示一个 lesson：**"真空"层级需要更精确**：
- 第一轮：把 audio editing 当成一个方向 → 245 篇
- 第二轮：把 audio editing 限定为 general audio → 仍有大量工作
- 第三轮（现在）：把 SFX AIGC 限定为 niche → 21 篇

**真正的真空 niche 是 **"特定子方向 + 特定工程模式"**的交集**——例如：
- "audio data curation via LALM agent"（data curation + LALM + agent 三者交集）
- 不是 "audio data curation"（已被做）

### 反思 2：21 vs 3 vs 0 的工程可行性差异

- **0 strict hits**：真空 niche，但要小心——可能是 query 太严
- **3 strict hits**：niche 存在，是早期阶段
- **21 strict hits**：已被开路，要差异化需 focus 子方向

**建议**：选择 0-5 strict hits 的方向 + 团队 AIGC 经验匹配的 = 最高 ROI。

### 反思 3：双重策略

基于这次核查：
- **真空 niche (T1)**: 高风险高回报——可抢占"首发"
- **早期 niche (T2, T4, T5)**: 中等风险中等回报——可补充完整 framework
- **已被开路 (T3)**: 高风险低回报——除非找到极 specific 差异化

**首选真空 niche + 次选早期 niche**。
