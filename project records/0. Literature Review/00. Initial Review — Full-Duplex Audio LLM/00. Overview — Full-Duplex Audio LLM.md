## 0. 摘要（Abstract）

"全双工音频大模型"（Full-Duplex Spoken Language Models, FD-SLMs）是指**同时听、同时说、可被打断、可生成副语言反馈**的语音-语言联合系统。其核心挑战是把传统 Automatic Speech Recognition（ASR） + Large Language Model（LLM） + Text-to-Speech（TTS） 串联管线（cascaded pipeline）里的几秒延迟与文本中间表示损失压下去，并在模型层面建模人类的"边听边说"行为（user interruption during model speech（barge-in）、listener's brief acknowledgment such as "uh-huh"（backchannel）、overlap、hesitation）。

这一轮 overview 把领域切成 7 条主线：

1. **奠基期（2022–2023）**：Generative Spoken Dialogue Language Model（dGSLM）、AudioLM、SoundStream/EnCodec/SoundStorm、VALL-E 等把"textless spoken dialogue"和"neural audio codec LM"两条线搭起来。
2. **2024 突破期**：Moshi（Kyutai, 2410.00037）首次做到 200ms 量级的真全双工语音-文本基础模型；同时间 LLaMA-Omni、Mini-Omni、GLM-4-Voice、Freeze-Omni、VITA-1.0/1.5、Qwen2-Audio、SpeechGPT、SALMONN-omni 等密集出现，把"语音 LLM"和"全双工"两条线汇合。
3. **2025 工业落地 + 学术 refinement 期**：OpenAI gpt-4o-realtime、Google Gemini Live、Kyutai Moshi 开源、Step-Audio、CosyVoice 3、Qwen2.5-Omni、PersonaPlex、FlexDuo、SpeechTokenizer、ZipVoice-Dialog；评测基准（Full-Duplex Benchmark（FD-Bench）、Full-Duplex-Bench、Multi-Turn Round Full-Duplex Benchmark（MTR-DuplexBench））和综述（Chen & Yu 2025, W. Cui 2025, WavChat）齐出。
4. **2026 互动对齐 + 解耦 + 专业化期**：Multi-Faceted Interactivity Alignment (Reinforcement Learning（RL）)、Hierarchical Acoustic-Semantic、Decoupling Conversational Dynamics、BayLing-Duplex、DuplexChat、Human-1 (Hindi)、Moshi-Face、DuplexSLA、Full-Duplex Spoken Language Models（FD-SLMs） Survey、IEEE International Conference on Acoustics, Speech and Signal Processing（ICASSP） 2026 Human-like Dialogue（HumDial） Challenge Track 等。
5. **音频编解码**（sound unit / codec）：EnCodec、SoundStream、SpeechTokenizer、Descript Audio Codec（DAC）、SpectroStream、WavTokenizer，是把"语音变成可被 LLM 操作的离散 token"的关键层。
6. **流式 ASR / TTS / 轮转**支撑：Zipformer、Paraformer、Whisper-streaming、Simul-Whisper、CosyVoice 2/3、F5-TTS、StyleTTS 2、NaturalSpeech 3、VITS-streaming、TurnGPT、SpectroStream 等。
7. **评测 / 数据 / 监控**：Full-Duplex Benchmark（FD-Bench）、Full-Duplex-Bench v1.5、Multi-Turn Round Full-Duplex Benchmark（MTR-DuplexBench）、Human-like Dialogue Challenge（HumDial） Challenge 2026、DuplexChat、J-CHAT 等。

整体观察（来自 2026 的两篇综述 + 60+ 篇一手机稿）：

- **范式跃迁**：2024 年之前是"cascade + Voice Activity Detection（VAD） + TTS"；2024 之后是"speech-text foundation model + interleaved token stream"；2025–2026 进一步切到"two-channel simultaneous generation + interaction-level alignment"。
- **开源/闭源分化**：OpenAI、Google、MiniMax、Kimi、字节（豆包）、阿里（CosyVoice/Qwen）、京东（JoyAI-Talker）都把全双工语音作为旗舰产品形态，但具体架构（cascaded controller / native duplex / MoE-Audio-LLM）尚未收敛。
- **评测与延迟**：业界已经意识到只报 Word Error Rate（WER） / Mean Opinion Score（MOS） 不够，2025–2026 起把 barge-in 准确率、流式 WER vs 离线 WER 退步、端到端 P50/P95 延迟、副语言自然度列入标准报告项。
- **关键开放问题**（来自 2026 综述 Chen & Yu 2025、Cui 2025、Multi-Faceted Alignment、Hierarchical Acoustic-Semantic）：单流 / 双流 token 设计的 trade-off、turn-taking 状态机的可控性、barge-in 触发与 VAD 误触发的矛盾、说话人身份在多码本 token 里的泄漏（speech token voiceprint attack, Lu 2026）、RL 互动对齐的数据构造。

## 1. 领域定义与核心术语

| 术语 | 简释 | 关键出处 |
|---|---|---|
| **FD-SLM (Full-Duplex Spoken Language Model)** | 同时听 + 同时说 + 可被打断的语音-语言基础模型 | Chen & Yu 2025 综述 |
| **Half-Duplex / Turn-based** | 必须等用户讲完才能回复的系统 | VAD 驱动的传统管线 |
| **Barge-in** | 用户在模型说话中插入打断 | dGSLM 时代就有相关实验 |
| **Backchannel** | "嗯 / 是的 / 点头" 之类的副语言反馈 | Mitsui 2023, dGSLM |
| **Native vs Cascaded** | 模型本身输出全双工 vs 控制器协调多个子系统 | FlexDuo (2502.13472) |
| **Interleaved Token Stream** | 把多流 token 拼成一个序列给 LLM | Moshi (2410.00037) |
| **Semantic / Acoustic Token** | 语义层（来自 HuBERT/k-means）和声学层（来自 neural codec）的两层 token | SpeechTokenizer (2308.16692) |
| **MoE-Audio-LLM** | 听觉 / 文本 / 思考模块分别用 MoE 子专家 | JoyAI-Talker (京东, 2025/2026) |

**两个最常被混用的名词**：
- **Speech LLM / Speech Language Model（SpeechLM）**：泛指任何"能听或能说"的 LLM，不一定全双工（GLM-4-Voice 早期是 turn-based）。
- **Spoken Dialogue Model (SDM)**：更窄，强调"对话"而非单轮"听 + 说"，dGSLM、Moshi 才是这一类。

## 2. 奠基期：2022–2023 把地基搭起来

### 2.1 文本无关（textless）对话生成

- **dGSLM — Generative Spoken Dialogue Language Modeling (Nguyen et al., 2203.16502, Transactions of the Association for Computational Linguistics（TACL） 2023)**  
  Meta / FAIR + ENS 的开创性工作：在没有文本的情况下，用 Hidden-Unit Bidirectional Encoder Representations from Transformers（BERT）（HuBERT） 离散单元 + dual-tower Transformer + cross-attention，在 Fisher 2000 小时双人对话数据上训练出能产生"嗯 / 是的 / 笑 / 轮流说话"的双通道 spoken dialogue。证明"不需要文本也能做 spoken dialogue"，并暴露出 textless 路径的两大难点：unit 字典的可解释性差、长程一致性差。

- **Mitsui 2023 — Towards human-like spoken dialogue generation between AI agents from written dialogue (2310.01088)**  
  NTT：在 Generative Spoken Dialogue Language Model（dGSLM） 之后尝试"从书面 dialogue → 口语 dialogue（含 listener's brief acknowledgment such as 'uh-huh'（backchannel） / 笑声 / 流畅 turn-taking）"的转换。

### 2.2 神经音频编解码（Neural Audio Codec）

把语音变成离散 token 的层，是所有语音-LLM 之前必须解决的事。2022–2023 这一波 codec 设计直接决定了后续 2024–2026 谁能用 LLM 跑通全双工。

| 模型 | 时间 | 关键设计 | 局限 / 备注 |
|---|---|---|---|
| **SoundStream** (Google) | 2021 | 端到端 residual Vector Quantization（VQ），24 kHz mono | 最早一批工业级 codec |
| **EnCodec** (Meta, 2210.13438) | 2022-10 | 24 kHz stereo + 量化器 + 判别器，码率 1.5–24 kbps | 后续 VALL-E、Moshi 都用它做声学 token |
| **AudioLM** (Google, 2209.03143) | 2022-09 | semantic token (Wav2Vec-BERT（w2v-BERT）) + acoustic token (SoundStream) 双层 | 首次把 LLM 思路用到 audio 生成 |
| **SoundStorm** (Google, 2305.09636) | 2023-05 | 非自回归并行解码 AudioLM 的声学 token | 解决 AudioLM 慢的问题；为 MusicLM / AudioPaLM 服务 |
| **VALL-E** (Microsoft, 2301.02111) | 2023-01 | 把 TTS 重写成 neural codec LM，prompt → 离散 codec tokens | "零样本 TTS"的开山；后被 SpeechTokenizer、SpectroStream 等替代 |
| **SpeechTokenizer** (ByteDance + 复旦, 2308.16692) | 2023-08 | **首个统一 tokenizer**：HuBERT semantic + Residual Vector Quantization（RVQ） acoustic，并设计 distill 损失让第一码本保留语义 | 直接服务 LLaMA-Omni / CosyVoice 2 之后的所有语音 LLM |
| **DAC** (Descript, 2306.00434) | 2023-06 | 24/44.1 kHz 高保真 + 改进量化器 | Audiobox、Vall-E-X 等用 |
| **WavTokenizer** (2024) | 2024 | 进一步压到 0.5–0.9 kbps 的超低码率 codec | 工业部署更友好 |
| **SpectroStream** (Google, 2508.05207) | 2025-08 | SoundStream 接班人，48 kHz stereo + 4–16 kbps | 当前最高保真 codec 之一 |

**对全双工的关键启示**：
- 语义 / 声学 token 解耦（SpeechTokenizer）是后期"边听边想 + 边生成语义 + 边流式出声学"的标准做法。
- 码率 vs 延迟的取舍：Moshi 用 Mimi = EnCodec-like codec @ 12.5 Hz，~80ms 一帧；CosyVoice 2 用 25 Hz Flow Matching；JoyAI-Talker 走更激进的 low-latency codec。

### 2.3 TTS / 神经声码器进化（为后期全双工流式 TTS 铺路）

- **VITS** (2021) — 端到端 VAE + flow + adversarial，单阶段 TTS。  
- **VITS 2 / VITS-streaming** — 流式 / 实时化变体。  
- **StyleTTS 2** (2306.07691) — 用大型 speech-LM + style diffusion + adversarial training 实现接近人声水平。  
- **NaturalSpeech 3** (2403.03100) — "factorized codec + diffusion"，zero-shot TTS SOTA 之一。  
- **F5-TTS** (2410.06885) — Flow Matching + ConvNeXt，整段 30s 流式生成，零样本。  
- **CosyVoice / CosyVoice 2 / CosyVoice 3** (2407.05407, 2412.10117, 2505.17589) — 阿里通义；CosyVoice 2 引入"chunk-aware flow matching"做低延迟 bi-streaming；CosyVoice 3 扩语言 / 扩域 / 扩后训练。  
- **VALL-E / VALL-E 2** — 离全双工更远，但提供 zero-shot timbre 控制思路。

### 2.4 流式 ASR（为后期全双工流式 ASR 铺路）

- **Zipformer** (Daniel Povey 团队, 2310.11230) — 比 Conformer 更快的 encoder；现在工业级 streaming ASR 默认 backbone（k2-fsa / sherpa-onnx）。  
- **Paraformer** (阿里达摩, 2206.08317) — 非自回归 + parallel transformer，FunASR / ModelScope 部署；后续 Paraformer-large / Paraformer-streaming。  
- **Whisper-streaming** (ufal/OLR, 2307.14743) — 把 Whisper 改成 local-attention + sliding window 的流式解码；不是 OpenAI 官方，但事实上成为开源流式 ASR 标配。  
- **Simul-Whisper** (2406.10052) — attention-guided truncation detection，做 streaming + 翻译。  
- **USM / Canary** (Google) — Universal Speech Model，2B 参数，100+ 语种，2023 起为 Gemini 做 streaming ASR。

### 2.5 轮转 / 副语言基础

- **TurnGPT** (Ekstedt & Skantze, 2020, 2022) — 用 GPT-2 预测 turn-taking，是后续"模型自身预测 turn shift"的早期思想来源。  
- **dGSLM** (前面提) — 副语言 + 轮流对话 + 双通道的奠基。  
- **SyncNet** — 用来评估 "lip-sync" / 跨模态同步的经典 objective，2023 后被借用来衡量模型自身 listener / speaker 通道同步性。  
- **Backchannel prediction** (Adiba et al., 2020) — 经典"嗯 / yes" 副语言分类与生成。

## 3. 2024 突破期：全双工 / 语音 Large Language Model（LLM） 同时爆发

这一年是分水岭：**Moshi** 把"全双工"从学术玩具变成"200ms 真可对话"的产品级 baseline；同一时间"语音-LLM"作为大类独立成型（GLM-4-Voice、Mini-Omni、Freeze-Omni、VITA-1.5、Qwen2-Audio 等密集出现）。两条线在 2024–2025 完成合流。

### 3.1 Moshi（Kyutai, 2024-09, arXiv:2410.00037）

> "Moshi: a speech-text foundation model for real-time dialogue" — Défossez, Mazaré, Orsini, Royer, Pérez, Jégou, Grave, Zeghidour (Kyutai AI, 前 FAIR / Google)。

**关键设计**：
- **架构**：单 Transformer Helium 7B 作 backbone，输入是 **interleaved token stream**——4 个流（user text / user audio / model text / model audio）以 12.5 Hz 步进交错。模型一次性自回归预测 4 流 token。
- **音频 codec**：Mimi = 训练自 EnCodec-like RVQ，第一码本为语义、其余为声学。
- **延迟**：理论 ~200ms（80ms 一帧 × 2.5 帧等待）。
- **训练数据**：2000h Fisher 双通道对话 + 大量 ASR/TTS 文本对齐数据。
- **范式**：完全抛弃 VAD 触发，模型自己决定何时"插话"。

**意义**：业界第一个"我能下载 weights 并自己跑出 200ms 全双工"的开源系统，2024-09 一举把整个领域的"延迟天花板"打下来。

### 3.2 同期重要模型

| 模型 | 单位 | arXiv | 类型 | 备注 |
|---|---|---|---|---|
| **Mini-Omni** | 不知名团队 | 2408.16725 | Turn-based with "any-model can listen while thinking in streaming" | streaming-style text + speech |

| **SALMONN-omni** | 清华 SALMONN 团队 (Yu et al.) | 2411.18138 | "Codec-free LLM"：直接用 hidden 特征 + Low-Rank Adaptation（LoRA） 接通双工 | 不依赖 codec LM，但需要大量训练数据 |

## 4. 2025 工业落地 + 学术 refinement 期

这一年全双工成为**产品标配**而非研究项目，OpenAI / Google / 国内大厂同时发力。学术端开始关心"互动对齐"和"评测"。

### 4.1 工业界旗舰系统

#### 4.1.1 OpenAI gpt-4o-realtime (2024-10 发布，2025 全面开放)

- **Application Programming Interface（API） 形态**：WebRTC + Server VAD + function calling + audio-in / audio-out 一条链路。
- **产品**：ChatGPT Voice Mode（高级语音模式，2024-07 灰度 → 2024-09 全量 → 2025 通用）。
- **延迟**：官方 ~232–320ms 平均响应（不同测评）。
- **范式**：cascaded（gpt-4o backbone + 自研 streaming ASR/TTS + server-side VAD），并非 native duplex，但用户体验上"听得见 + 几乎能打断"。

#### 4.1.2 Google Gemini Live (2024-08 公布，2025-03 全面推送)

- **架构**：Gemini 2.0 Flash 多模态实时（audio + video + screen share + text）。
- **特点**：天然多模态、端侧 / 云端混合部署（Pixel 优先）。
- **关键卖点**：低延迟、function calling、长时间记忆。

#### 4.1.3 Kyutai Moshi / Moshi 开源生态

- 2024-09 论文 + weights；2025 年衍生：Moshi-Face (2606.21970, 加入人脸生成)、Human-1 Hindi (2604.23295)、Environmental Footprint (2604.11154) 等。
- "Decoupled"派生：SyncS2S、Text-AB 2609.09255 (Alignment-Free Text-Audiobox for Full-Duplex)。

#### 4.1.4 阿里 / 通义 — Qwen2.5-Omni (2025-03, 2503.20215)

- **架构**：**Thinker-Talker**：Thinker 是 Qwen2.5-Omni 的 LLM backbone，Talker 是 dual-track autoregressive speech decoder。
- **亮点**：原生音视频多模态 + 实时 + B 站级多语种支持。
- **意义**：把"Thinker-Talker"作为模版，京东 JoyAI-Talker 后期直接借鉴。

#### 4.1.5 StepFun — Step-Audio (2025-02 公布)

- **架构**：130B 参数（业内首批百亿级 speech-LLM）；统一 LLM backbone，**直接生成 audio token**（不经 cascade）。
- **亮点**：原生支持 voice editing / role-play / AI-Generated Content（AIGC） 风格化。

#### 4.1.6 NVIDIA PersonaPlex (2602.06053, 2026-01)

- **架构**：Moshi-style duplex backbone + **hybrid system prompt**（角色 + 文本 + 声音样本三种 prompt 联合）。
- **亮点**：在保持 full-duplex 能力下首次做到 voice + role 的可控生成；2026-01 开源。

#### 4.1.7 字节跳动 — 豆包（Doubao）实时语音 / Seed-ASR

- 字节豆包 2024 推出实时语音对话产品（手机 / 智能硬件）。
- Seed-ASR 系列：contextual biasing ASR，与豆包语音强耦合。
- 公开 paper 较少，主要在开发者大会介绍。

#### 4.1.8 MiniMax — Speech-01 / abab-speech (2025)

- MiniMax 2025 上线 Speech-01 语音模型，主打"超低延迟 + 高自然度"，定位 ChatGPT Voice 国产替代。

#### 4.1.9 月之暗面 — Kimi 实时语音 (2025-Q2)

- Kimi 上线实时语音，2025-Q2 起在 Kimi App 全量。

#### 4.1.10 京东 — JoyAI-Talker (2025-Q4 / 2026 公开)

- 架构：**解耦 Thinker-Talker + 48.9B Mixture of Experts（Mixture of Experts（MoE））**（其中 Thinker 是大 MoE LLM，Talker 是小 MoE 语音解码器）。
- 卖点："**零退化认知**"（thinking 不因接语音而降智） + "**拟人共情生成**"（empathy-aware speech） + "**即插即用全双工状态机**"（state machine 模块化）。
- 公开技术细节有限，主要在京东 JD Tech 报道 + 知乎技术文章。

#### 4.1.11 阿里 / 达摩 — CosyVoice 3 (2505.17589, 2025-05)

- 主要改进：扩语言 / 扩域 / 扩数据；保持"chunk-aware flow matching"低延迟设计。
- 与 Qwen2.5-Omni 配合做完整 duplex 链路。

#### 4.1.12 Hume — EVI 3 (2025)

- 主打"情感 / 共情语音对话"，interruption + emotion + prosody 都做。
- 不是 native duplex，但产品体验最自然。

#### 4.1.13 Sesame — Maya / Miles (2025)

- 硅谷 start-up，主打"voice presence"（声音的在场感）。
- 不是 native duplex，但因为声音自然度极高引发关注。

### 4.2 2025 学术新工作

#### 4.2.1 评测 / Benchmark

- **FD-Bench** (Peng et al., 2507.19040, NTU) — 端到端全双工评测管线，LLM + TTS + ASR pipeline 模拟用户，重点评估 interruption handling。  
- **Full-Duplex-Bench v1.5** (Lin et al., ICASSP 2026, 10.1109/icassp55912.2026.11463576) — 2026 ICASSP 上发布的 overlap-handling 评测。  
- **MTR-DuplexBench** (H. Zhang et al., 2025, 被引 11 次) — 综合性 FD-SLM 评测。  
- **Moshi-1.5 评测集** + **Multi-Faceted Interactivity Alignment benchmark** (2606.11167, 2026) — 互动层指标。  
- **ICASSP 2026 HumDial Challenge — Full-Duplex Interaction Track** (2604.21406, Wang et al., 2026-04) — 把 Full-Duplex（FD） 列为正式赛道。

#### 4.2.2 全双工控制 / 双工解耦

- **FlexDuo** (Liao et al., 2502.13472, 字节) — 即插即用全双工控制模块，把 duplex controller 与对话模型解耦；模块化思想借鉴自工业 cascade 经验。  
- **F-Actor** (Züfle et al., 2601.11329, 2026-01) — "可控对话行为"全双工模型，用 instruction-following 控制 conversational behaviour。  
- **Decoupling Conversational Dynamics in Full-Duplex Models** (2026-07) — 把"语义动态"和"副语言 / 打断动态"分离建模。  
- **BayLing-Duplex** (2606.14528, 2026-06) — 单个 autoregressive LLM 直接做 native 全双工；显式对比 LLaMA-Omni / GLM-4-Voice 的 VAD 限制。  
- **DuplexSLA** (2605.20755, 2026-05) — 在 duplex backbone 里加 **action channel**，让模型能做 tool-call / agentic planning 同时说话。  
- **How Should Large Language Models（LLMs） Listen While Speaking?** (2605.10199, Lu et al., 2026-05) — "user-stream routing" 系统研究；把 user 音频如何灌入 LLM 当成显式架构问题。  

#### 4.2.3 互动对齐 / Reinforcement Learning（RL）

- **Multi-Faceted Interactivity Alignment in Full-Duplex Speech Models** (Ohashi, Zeghidour, Défossez, Kharitonov, 2606.11167, 2026-06) — 用 RL 同时对齐 silence / turn-taking / responsiveness 三个互动维度。Ohashi 是 Kyutai + 京都大学。  
- **Overcoming State Inertia in FD-SLMs via Activation Steering** (2606.11386, 2026-06, MIT + Apple) — 揭示 FD-SLM 的"state inertia"（listen / speak 状态切换有 inertia），并提出 activation steering 解。  
- **Synchronization and Turn-Taking in Full-Duplex Spoken Dialogue Models（FD-SDMs）** (Riera et al., 2605.20356, 2026-05) — 借鉴人脑神经耦合，用 Moshi 双实例模拟"沟通同步性"。

#### 4.2.4 数据集 / 大规模 duplex 数据

- **DuplexChat** (Nakata et al., 2607.04941, 2026-07) — 首个开源 speaker-separated full-duplex dialogue speech corpus，pipeline 可从公开 podcast 批量构造。  
- **J-CHAT** (Nakata et al., 2407.15828) — 76k 小时日语 spoken dialogue。  
- **Human-1 by Josh Talks** (2604.23295) — 26,000 小时印地语 real spontaneous conversation。  
- **ZipVoice-Dialog** (2507.09318) — 非自回归 spoken dialogue generation。  
- **SALMONN-omni data** (见前) — 也提供了训练 recipe。

#### 4.2.5 副语言 / 共情 / 角色控制

- **VITA-QinYu** (2605.06765, 2025-05, Tencent) — expressive SLM，含 role-play + singing。  
- **Moshi-Face** (2606.21970, 2026-06) — 全双工 spoken dialogue 基础上加 facial motion。  
- **PersonaPlex** (NVIDIA, 2602.06053) — 角色 + 声音 + 文本 三模态 prompt 联合控制。  
- **Towards a Japanese Full-duplex Spoken Dialogue System** (Ohashi et al., Interspeech Conference（Interspeech） 2025) — Moshi 衍生到日语。

## 7. 关键开放问题与方向（来自 2025–2026 综述）

> 这一节是给后续 "细方向 literature review" 留的口子。

1. **单流 vs 双流 token 设计**（Interleaved vs Dual-track）  
   - Moshi 走 interleaved (4 streams)，Qwen2.5-Omni 走 dual-track (thinker / talker)，JoyAI-Talker 走 MoE 解耦。  
   - 各有 trade-off，缺统一评测。

2. **user interruption during model speech（barge-in） 触发的可控性**  
   - 过度敏感 → 把 "嗯" 当打断。  
   - 过度迟钝 → 用户体验割裂。  
   - Multi-Faceted Alignment (RL) 是当前最有希望的解。

3. **说话人身份 / 声纹在 speech token 中的泄漏**  
   - Lu 2026 揭示 duplex 模型输出的 speech token 可被重建为声纹；需要 privacy-preserving 训练 / 推理。

4. **评测缺标准**  
   - WER / MOS 不足以反映 duplex 体验；需要 barge-in 准确率、overlap 容错、P50/P95 端到端延迟、互动自然度（人类偏好）等。  
   - 2025–2026 多个 benchmark 涌现（FD-Bench、Full-Duplex-Bench、MTR-DuplexBench）但未统一。

5. **认知能力不因接语音退化**  
   - JoyAI-Talker 的 "零退化认知" 是 LLM 接入语音的硬骨头：thinking tokens 被 speech stream 干扰，推理质量下降。  
   - 解决思路：MoE 解耦 / activation steering / 显式 thinking channel。

6. **长时记忆 / 跨轮一致性**  
   - 双工对话可能持续数十分钟甚至数小时；当前几乎所有模型都会"忘前文"。  
   - DuplexSLA 之类的 action channel 是一个方向，但还远未成熟。

7. **端到端延迟分层测量**  
   - 按本项目 `RULES.md` 的要求：ASR 首字、TTS 首块、前向耗时、chunk 大小要分层。  
   - 业界尚未形成统一 latency 报告格式。

8. **数据 / 评测多语种扩展**  
   - 当前多数 duplex 评测在英语 / 中文，Hindi (Human-1)、日语 (J-CHAT) 刚开始。

9. **AI-Generated Content（AIGC） 维度（个性化 / 风格 / 情感）**  
   - 2025–2026 大量 AIGC 玩家进入（Step-Audio、PersonaPlex、Moshi-Face），但 AIGC 与 duplex 的耦合评测缺。

10. **安全 / 隐私 / 越狱**  
    - 全双工模型可被语音 prompt injection 攻击；需要专门的 red-team 流程。

## 8. 对本项目（FullDuplexLLM）研究方向的启示

> 这一节是连接 lit review 与本项目 ARCHITECTURE 的桥梁，留给后续 "细方向" 报告展开。

- **子方向 1（流式 ASR）**：Zipformer + Paraformer 是工程基线；Simul-Whisper 是开源便捷选择；USM / Canary 是工业参考。

- **子方向 6（多模态双工）**：Moshi-Face / VITA-1.5 / Qwen2.5-Omni / Gemini Live / GPT-4o 视觉模态。
