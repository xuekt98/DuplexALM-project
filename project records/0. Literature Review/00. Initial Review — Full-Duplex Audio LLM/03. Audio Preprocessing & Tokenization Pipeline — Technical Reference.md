> 范围：流式 ASR / TTS / 语音 LLM / 全双工语音 LLM 的前端处理与 token 化

## 0. 全链路速览

```
[mic / file @ 16-48kHz]
   ↓ ① resample → 16k / 24k
[PCM mono]
   ↓ ② chunking → 30/40/80ms frames (streaming)
[Frame batch]
   ↓ ③ frontend → log-mel / learned filterbank / codec encoder
[Feature / Latent]
   ↓
   ├── ④A continuous path: encoder → projector → LLM embedding
   └── ④B discrete path: RVQ → token IDs → LLM vocab 扩展
   ↓
[LLM / Decoder] → text tokens → (TTS) → PCM output
```

## 1. 采样率 / 通道

| 用途 | 采样率 | 通道 | bit | 代表 |
|---|---|---|---|---|
| 流式 ASR | **16 kHz** mono | 1 | int16 | Whisper / Zipformer / Paraformer |
| 流式 TTS | **24 kHz** mono | 1 | int16 | CosyVoice 2/3 / F5-TTS / NaturalSpeech 3 |
| Duplex codec | **24 kHz** mono | 1 | float32 | Mimi (Moshi) / EnCodec / Descript Audio Codec（DAC） |
| 双工训练数据 | **16 kHz × 2 ch** | 2 | float32 | Fisher (Generative Spoken Dialogue Language Model（dGSLM）) |
| 工业部署输入 | 16k | 1 | 视 codec | 视后端 |

工具链：`soundfile` / `librosa.resample` / `torchaudio.functional.resample` / `ffmpeg -ar 16000 -ac 1 -f s16le`。

## 2. 流式分帧 (chunking)

| 模型 | 帧长 | hop | 帧率 | 备注 |
|---|---|---|---|---|
| **Moshi / Mimi** | 80ms | 80ms | 12.5 Hz | 1 帧 → 4 流 token |
| **CosyVoice 2** | 80ms | 80ms | 12.5 Hz | chunk-aware Flow Matching |
| **Whisper-streaming** | 30s 窗口 | 1s 滑窗 | 1 Hz | 全 utterance 上下文 + 滑窗 |
| **Zipformer** | 40ms | 40ms | 25 Hz | 左 64 帧 + 右 8 帧 context |
| **Paraformer** | 40ms | 40ms | 25 Hz | 非自回归 |
| **AudioLM / SoundStorm** | 50ms (代码本 1) + 10ms (代码本 2) | 50ms | 20/100 Hz | 多尺度码本 |
| **Simul-Whisper** | 20–30s | streaming | 视配置 | attention-guided truncation |

**两种 chunking 策略**：

- **固定帧 + look-ahead**（Zipformer）：左 64 + 右 8 帧，输出 1 帧推进。
- **滑动窗口 + truncate**（Whisper-streaming / Simul-Whisper）：30s 窗口 + 滑窗或 attention 截断。

**全双工特殊**：listener / speaker 两条流独立 chunking，但时间戳必须共享同一时钟（Moshi 12.5 Hz）。

## 3. 前端特征 (frontend)

### 3.1 传统 mel 路径（ASR 系）

```
PCM → pre-emphasis → Hann(25ms) → FFT(512) → mel(80 bin) → log → CMVN → [T, 80]
```

- Whisper: 80-bin log-mel, 25ms window, 10ms hop → 100 Hz。
- Zipformer: 8-d + 80-d 多分辨率混合前端。
- Paraformer: 80-bin log-mel。

### 3.2 学习式 frontend（speech-LLM 系）

- **AudioLM / Moshi (Mimi)**: 跳过 mel；raw → Conv1d + SEANet → latent → Residual Vector Quantization（RVQ） → tokens。
- **Wav2vec 2.0 / Hidden-Unit Bidirectional Encoder Representations from Transformers（BERT）（HuBERT）**: raw → 7 层 Convolutional Neural Network（CNN） (stride 320 @ 16kHz) → 50Hz → Transformer → k-means → 单元 token。
- **SpeechTokenizer** (2308.16692): HuBERT k-means (semantic) + EnCodec RVQ (acoustic) → **双层 token**（第一码本语义 + 后续码本声学）。

**对比**：

- ASR 系多走 mel frontend。
- speech-LLM 系多走 neural codec frontend。
- Codec 优势：保留 speaker / prosody / emotion；LLM 友好；训练-推理一致。
- Codec 劣势：码率 / 字典大；"语义"和"声学"纠缠。

## 4. 连续路径 (Continuous Path)

```
[Feature] → [Encoder] → [Continuous hidden states B×T×D_enc]
                              ↓
                         [Projector: linear / Q-Former / perceiver]
                              ↓
                         [B×T×D_LLM embedding]
                              ↓
                         [插入 LLM token sequence]
```

**代表**：

- **Qwen2-Audio**: Whisper encoder (1280-d) → 线性 → Qwen-7B。
- **SALMONN-omni**: Whisper + BEATs 双 encoder → Querying Transformer（Q-Former） → Vicuna-13B。
- **VITA-1.0/1.5**: parallel audio encoder + LLM。
- **GLM-4-Voice**: Audio tokenizer + GLM-4-9B。

**优点**：训练简单；encoder 已有 Automatic Speech Recognition（ASR） / 音频预训练。
**缺点**：连续浮点张量大；不可离散采样。

---

## 5. 离散路径 (Discrete / Codec Path)

```
[Raw PCM] → [Codec Encoder (SEANet/ConvNeXt)]
                ↓
[Continuous latent B×T_lat×D_lat, e.g. 12.5Hz × 1024-d]
                ↓
[Residual Vector Quantization (RVQ): 8-32 层码本]
                ↓
[每帧每层选一个 ID → B×T_lat×N_layers 个 token]
                ↓
[沿时间展开: B × (T_lat × N_layers) 单一 token sequence]
                ↓
[LLM vocab 扩展: 152k + N_layers×1024 = 160k+]
                ↓
[LLM 与文本 token 联合训练]
```

### 5.1 主流 codec 速查

| Codec | 帧率 | 码本数 | 单帧 token | 字典大小 | 用途 |
|---|---|---|---|---|---|
| **EnCodec** (2210.13438) | 75 Hz × 8 | 8 | 8 | 1024 | VALL-E, Moshi-Mimi |
| **SoundStream** | 50 Hz × 多 | 多 | 多 | 1024 | AudioLM, MusicLM |
| **SpeechTokenizer** (2308.16692) | 50 Hz × 8 | 8 (1 语义 + 7 声学) | 8 | 1024 | CosyVoice 2, LLaMA-Omni |
| **Mimi** (Moshi) | 12.5 Hz × 8 | 8 | 8 | 2048 | Moshi |
| **DAC** (2306.00434) | 50/100 Hz × 9-12 | 9-12 | 9-12 | 1024 | Audiobox |
| **SpectroStream** (2508.05207) | 25 Hz × 多 | 多 | 多 | 大 | Google 2025 |
| **WavTokenizer** | 75 Hz × 1-4 | 1-4 | 1-4 | 4096 | 极低码率 |

### 5.2 Moshi 的 4 流交织 (interleaved)

```
Time:        t=0  t=1  t=2  t=3 ...   (12.5 Hz)
Stream 0:    [u0] [u1] [u2] [u3]     user text token
Stream 1:    [v0] [v1] [v2] [v3]     user audio semantic token
Stream 2:    [m0] [m1] [m2] [m3]     model text token
Stream 3:    [w0] [w1] [w2] [w3]     model audio semantic token
   ↓
[Interleave: u0 v0 m0 w0, u1 v1 m1 w1, ...]
   ↓
[Helium 7B 一次自回归预测下一时间步的 4 个 token]
   ↓
80ms 出一组 (4 token)，理论延迟 ~200ms (2.5 帧等待)
```

## 6. LLM 集成方式

### 6.1 直接扩 vocab（codec 路径）

- 原 vocab 152,064 + N × 1024 = 160k+ 词表。
- 一个 transformer 同时做文本 + 音频自回归。
- 代表：Moshi / Qwen2.5-Omni / CosyVoice 2 / SpeechGPT。

### 6.2 Projector 投影（encoder 路径）

- encoder 输出连续向量 → linear / Q-Former / perceiver resampler → LLM embedding。
- 代表：Qwen2-Audio / SALMONN / VITA-1.0/1.5 / GLM-4-Voice。

### 6.3 全双工特殊

- **时间戳对齐**：listener / speaker 共享同一时钟。
- **partial decoding**：listener 未听完就生成 → causal mask + look-ahead 控制。
- **vad token**：很多模型引入"听 / 说 / 沉默"特殊 token 作为隐式 Voice Activity Detection（VAD）。

## 7. 工业 / 工程层细节

### 7.1 流式 buffer 设计（简化）

```python
import collections
import numpy as np

class AudioBuffer:
    def __init__(self, sr=24000, chunk_ms=80, history_ms=4000):
        self.sr = sr
        self.chunk_samples = sr * chunk_ms // 1000
        self.history = collections.deque(maxlen=sr * history_ms // 1000)
    
    def push(self, pcm_chunk):  # 来自 sounddevice callback
        self.history.extend(pcm_chunk)
        while len(self.history) >= self.chunk_samples:
            frame = np.array(list(self.history)[:self.chunk_samples])
            yield frame
            for _ in range(self.chunk_samples):
                self.history.popleft()
```

### 7.2 端侧部署常见坑

- 采样率不一致：mic 默认 48k/44.1k → 重采样到 16k/24k。
- buffer underrun / overrun：实时流必须 ring buffer。
- **first-packet latency**：从 mic 启动到第一个 token 输出单独度量。
- **user interruption during model speech（barge-in） 截断**：用户开始说话 → 立即清空 output buffer。

### 7.3 duplex 特殊

- **听/说通道解耦**（FlexDuo / DuplexSLA）：listener / speaker 走独立模块，共享时间同步器。
- **action channel**（DuplexSLA, 2605.20755）：audio/text 之外再加 "action" 流，支持 tool call。
- **state inertia 解**（2606.11386）：listen/speak 切换有 inertia，activation steering 缩短切换时间。

## 8. 关键术语对照

| 术语 | 含义 |
|---|---|
| **mel-spectrogram frontend** | ASR 传统的 log-mel 特征 |
| **codec frontend** | speech-LLM 常用的神经音频编解码器输出 |
| **RVQ (Residual Vector Quantization)** | 多层码本量化，残差近似 |
| **Semantic / Acoustic token** | 第一码本（语义）+ 后续码本（声学） |
| **Interleaved stream** | 多流 token 在时间维度交织（Moshi 4 流） |
| **Thinker-Talker** | Qwen2.5-Omni / JoyAI-Talker 用：text/audio 双轨 |
| **Vocab extension** | 把 codec 码本加到 LLM 词表 |
| **Projector** | 把 encoder 连续输出投影到 LLM 维度 |
| **First-packet latency** | mic 启动到首 token 输出的时间 |
